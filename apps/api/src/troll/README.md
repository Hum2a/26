# Trolls

[Home](../../../../README.md) · [Documentation](../../../../docs/README.md) · [Event runbook](../../../../docs/event-runbook.md)

One token per guest for the whole game. It unlocks on the second question. Spending the token and accepting the effect are one stored action. The same request returns that result. A different request cannot spend a second token.

Each target has one transient slot and one persistent slot. A second effect for a full slot waits. A third is rejected and does not spend the token. A waiting effect that cannot start before its phase ends expires, and its token is refunded once. An effect that already started is not refunded. Pause freezes the effect timer with the other gameplay timers. Skip and advance settle effects whose phase has ended. The host can cancel a running troll. Reconnecting reads the stored effect and does not start it again.

Stage announcements wait in one short queue of three. A further announcement is dropped. The host can dismiss the announcement that is showing. Demo cues carry a label and, when they have sound, a short file or an accepted voice clip.

Presentation effects do not change the player id or the score ledger. A nickname swap changes the name on screen only. Hidden score hides that phone's own points. The answers keep their ids. A dodging button can be stopped with Answer anyway, and it settles after at most three seconds. While it is active, a question that sets `suppressSpeedBonus` awards no speed points.

`double` changes one player's own award. It runs after the question's own points, only when that question lists `modifiers: ["double"]`, and only for an accepted double that is still active. A positive award is doubled. A zero award stays zero. Host adjustments are separate and are not doubled.

## Stage sound

The stage has Start show and a mute control. Browsers will not play audio until Start show runs from a click on that screen. A refresh asks again. M toggles mute, and the small icon shows when the stage is muted. Mute is remembered for the tab and stops the sound that is playing.

Entertainment audio is not exactly-once if the browser crashes. A cue that is already on screen when the stage loads, already played, muted, or left over from an earlier question is dropped. A cue that arrives while sound is locked waits for Start show, then plays once. The played cue id is stored in the tab. Score changes and the troll token stay exactly-once in the room.

Live typing keeps only the latest draft, in memory, and only the stage snapshot includes it. Closing the phone, hiding it, changing phase, or restarting the room clears that draft. The sent answer is still the normal stored answer. The effect is offered only when the question's attribution is `live`.

A voice troll records on the phone, plays a preview, and can be recorded again. The clip is checked through the media pipeline, then held until that question's reveal. Skipping the question drops it. A missing microphone does not spend the token and does not block the question.

A theme song uses the persistent slot and keeps going across questions until the podium, or until four score cues have been queued. Each scores phase queues one sting. The cue id is stored, so a reconnect does not treat an old reveal as a new one. Pause and resume keep the same cue id.

The jingle at `apps/web/public/assets/demo-sting.wav` is generated by `node scripts/generate-theme-sting.mjs` (a 2.4 second fanfare). Replace it with any short PCM WAV under about three seconds. The label in the catalogue is `Theme jingle`.

## Implemented

| Effect            | Slot       | What the guest sees                                                     |
| ----------------- | ---------- | ----------------------------------------------------------------------- |
| Screen invasion   | Transient  | The troller's driver face (or name) flooding the screen, with Dismiss   |
| Call from Mum     | Transient  | A full incoming call: Decline, or Answer for a short call from Mum      |
| Cracked screen    | Transient  | A shattered-glass layer that taps pass through, with Dismiss            |
| Dodging button    | Transient  | The send button moves for at most three seconds, with Answer anyway     |
| Nickname swap     | Transient  | The two names trade places on screen                                    |
| Hidden score      | Transient  | The target's own points are hidden, with Show my score                  |
| Double or nothing | Persistent | The target's award for that question is doubled, or stays zero          |
| Live typing       | Transient  | One stage draft at a time, only on a live-attribution question          |
| Voice clip        | Persistent | A checked clip of at most 3 seconds, played on the stage at the reveal  |
| Theme song        | Persistent | A short sting on that player's later score reveals                      |
| Sponsor break     | Transient  | A fake sponsor line about the target on the stage, an ad on their phone |

Captioned photos use the same cue card. An accepted photo can show there with the caption `Photo from` the nickname. The illustrative colour question allows double or nothing. The illustrative candles question suppresses speed points while the button is dodging, and its attribution is `live`, so live typing is offered there.

## Input sabotage

`apps/web/src/troll/sabotage-trolls.tsx`. These act on the answer controls of any question design through the page itself: option buttons (`button[aria-pressed]`), sliders (`input[type=range]`) and text inputs, skipping the troll panel and the photo wall. Each puts everything back when it ends. The answer sent is whatever the controls hold. Each sets `disruptsSubmission`, so a question with `suppressSpeedBonus` gives no speed points while it runs (`submissionDisrupted` now reads the catalogue flag rather than naming `yield`). `questionKinds` limits each one to questions it can affect; elsewhere it is not offered and the room refuses it.

| Effect              | Questions                               | What the target sees                               |
| ------------------- | --------------------------------------- | -------------------------------------------------- |
| Shuffled answers    | choice, vote, guess, duel, finale, rank | Options swap places every 1.5 seconds              |
| Lost in translation | choice, vote, guess, duel, finale, rank | Option text in Pig Latin                           |
| Possessed slider    | slider                                  | The slider runs backwards and drifts               |
| Reverse typing      | typed, vote                             | Each letter goes in at the front                   |
| Autocorrect         | typed, vote                             | Finished words "corrected" (love becomes tolerate) |
| Character limit     | typed, vote                             | Twelve characters only, the rest cut               |
| Haptics storm       | any, while answering                    | The phone buzzes in random bursts                  |

`test/troll-catalogue.spec.ts` checks every kind is defined within the snapshot's 40-character limits and that no label still says "Demo".

## Identity

The silly name and Guest 14 go through `displayNickname`, so every screen that shows names (player lists, reactions, standings, the stage) shows the new one while the troll runs, and the real name returns when it ends. Stored names, scores and answers never change. When several apply, the silly name wins, then Guest 14, then a nickname swap. `sillyNameFor` picks from a fixed list by the effect id, so the name is stable for the whole troll.

| Effect          | Slot      | What happens                                                 |
| --------------- | --------- | ------------------------------------------------------------ |
| Silly name      | Transient | A name like "Captain Wrong" on every screen for 45 seconds   |
| Guest 14        | Transient | "Guest 14" on every screen for 45 seconds                    |
| Fake last place | Transient | The target's phone shows them last below real players' names |

## Stage theatre

Built on the stage cue queue. The stage reads a cue as "<label> <asset>.", so asset labels never give a joke away.

| Effect           | When it plays                      | What the stage shows                                                   |
| ---------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| Instant replay   | The reveal of that choice question | "Amina went with “Pink”." (not judged: the reveal does that)           |
| Speech!          | The scores after that question     | "Amina, the floor is yours." for 8 seconds                             |
| Fake exit        | Straight away                      | "Amina has left the party.", then "Only joking." The phone plays along |
| Zoom and enhance | Straight away                      | The target's latest photo the stage may show, zooming slowly in        |

Replay and speech use the persistent slot, wait for their phase in `enqueueTheatreCues` (run by `settleTrolls`), play once and end. `zoomPhotoFor` takes a question photo, driver face, or a wall photo that has been on screen, never a hidden or pending one; with none, the room refuses the troll and the token is not spent.

## Scoring

Score trolls only run on a choice question that lists the kind in `modifiers` (`"double"`, `"steal"`, `"robin-hood"`, `"share"`). Elsewhere they are not offered and the room refuses them. No question pack opts in to the three new ones yet; add them to a question's `modifiers` to use them. They use the persistent slot, last the question and settle at the reveal. `applyPointTransfers` runs after every award is known, in the fixed order steal, Robin Hood, share, so the result never depends on send order. Points are only moved, never created, and nothing goes below zero. The ledger detail records each move (`*stole`, `*stolen`, `*robbed`, `*robin-hood`, `*shared`). Host adjustments are separate and untouched.

| Effect        | What happens at the reveal                                                                |
| ------------- | ----------------------------------------------------------------------------------------- |
| Steal         | The troller takes half (rounded down) of the target's points for that question            |
| Robin Hood    | The target's points go to the guest in last place before this question (never the target) |
| Shared score  | Troller and target split their combined points; the odd point goes to the target          |
| Public vote   | On a vote question, the stage shows who the target voted for                              |
| Misattributed | On a typed or vote question, the stage claims the target wrote another guest's answer     |

Public vote and misattributed change nothing but the stage caption.
